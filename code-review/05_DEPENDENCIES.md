## DEP-001: Отсутствие профиля оптимизации `[profile.release]` в Cargo.toml

| Поле | Значение |
|---|---|
| **Идентификатор** | DEP-001 |
| **Серьёзность** | 🟡 Medium |
| **Файл и строки** | [`Cargo.toml:1-33`](file:///c:/Users/User/Documents/antigravity/amazing-shannon/Cargo.toml) |
| **Категория** | Конфигурация сборки и размер бинарного файла |

### ❌ Проблема
В манифесте проекта `Cargo.toml` не определены параметры оптимизации для релизной сборки `[profile.release]`. По умолчанию компилятор `rustc` сохраняет отладочные символы, использует стандартный уровень оптимизации `opt-level = 3`, делит код на множество параллельных блоков генерации кода (`codegen-units = 16`) и не применяет глобальную межмодульную оптимизацию (Link-Time Optimization, LTO).
Для утилиты, предназначенной для постоянной работы в фоновом режиме в системном трее Windows, критически важны минимальный рабочий набор страниц памяти (Working Set) и компактный размер бинарника.

### 📍 Текущий код
```toml
# В Cargo.toml секция [profile.release] полностью отсутствует
```

### 💥 Последствия
1. Размер итогового исполняемого файла составляет ~7–9 МБ вместо потенциальных 1.5–2.5 МБ.
2. Процесс потребляет на 20–30% больше оперативной памяти при старте из-за отсутствия агрессивного удаления неиспользуемого кода на этапе линковки.

### ✅ Решение
Добавить в конец файла `Cargo.toml` специализированную конфигурацию для релизных сборок:

```toml
[profile.release]
opt-level = "z"        # Оптимизация под минимальный размер бинарника
lto = true             # Включение агрессивной Link-Time Optimization через все зависимости
codegen-units = 1      # Максимальная оптимизация всей программы единым блоком
panic = "abort"        # Отключение таблиц раскрутки стека (уменьшает бинарник на сотни КБ)
strip = true           # Автоматическое удаление отладочных символов из финального exe-файла
```

### 💡 Объяснение
- `opt-level = "z"` отдаёт приоритет уменьшению размера инструкций, что улучшает попадание в кэш инструкций L1i процессора.
- `lto = true` позволяет компилятору удалить неиспользуемые фрагменты API `windows-rs` и `crossterm`.
- `strip = true` устраняет необходимость вручную запускать внешние утилиты очистки отладочных таблиц.

### ⏱ Сложность исправления
Низкая (2 минуты).

### ❌ Проблема
Проект использует крейт `windows` версии `0.58`. Экосистема `windows-rs` от Microsoft развивается очень динамично, и в новых версиях исправляются ошибки безопасности типов для структур Win32/WinRT и улучшается производительность биндингов.
