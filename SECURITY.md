# Политика безопасности GhostClip Shield (`SECURITY.md`)

## 1. Модель угроз и границы защиты

**От чего защищает GhostClip Shield:**
- случайная утечка скопированных API-ключей, токенов, JWT, строк подключения к БД, приватных ключей и банковских карт при забывчивости пользователя (таймер самоуничтожения в буфере обмена);
- оседание конфиденциальных данных в истории буфера Windows `Win+V` и облачной синхронизации (приватная перезапись с `CanIncludeInClipboardHistory = 0`, `CanUploadToCloudClipboard = 0` и вызов WinRT `ClearHistory()`);
- распространение трекинг-параметров в ссылках (`utm_*`, `fbclid`, `gclid`, `si`, `yclid` и др.) и скрытых водяных знаков Zero-Width (`\u200B`, `\u200C`, `\u200D`, `\uFEFF` и т.д.);
- утечка содержимого буфера через локальный журнал аудита (`clipboard_access.log`);
- случайное отключение защиты (отключение кнопки `[X]` консоли, сворачивание в системный трей, блокировка повторного запуска через мьютекс `Local\GhostClipShield`).

**Что находится вне зоны ответственности программы:**
- вредоносное ПО с правами администратора или `SYSTEM`, драйверы уровня ядра (руткиты, ядерные кейлогеры);
- физический доступ злоумышленника к разблокированной сессии Windows (до срабатывания таймера или ручной команды паники `Ctrl + Shift + X`);
- аппаратный перехват ввода и прямые дампы оперативной памяти других процессов с повышенными привилегиями.

---

## 2. Приватность и отсутствие телеметрии

- **100% локальная работа:** GhostClip Shield не открывает сетевых сокетов, не отправляет телеметрию, аналитику или содержимое буфера на внешние серверы.
- **0 сторонних runtime-зависимостей:** в работе программы используется только стандартная библиотека Python 3.10+ и системные DLL Windows (`user32`, `kernel32`, `shell32`, `winreg`) через `ctypes`.
- **Безопасный журнал `clipboard_access.log`:**
  - обычный текст никогда не сохраняется в открытом виде — фиксируется только метаинформация `[текст, N симв.]`;
  - обнаруженные секреты всегда маскируются (`sk-p•••UV`), как в консоли, так и в файле журнала;
  - при достижении `1 МБ` журнал автоматически ротируется в `clipboard_access.log.1`.

## 3. Проверка целостности `GhostClip.exe` и Windows SmartScreen

Каждый релизный бинарник `GhostClip.exe` собирается прозрачно в публичном CI/CD ([`.github/workflows/release.yml`](.github/workflows/release.yml)) из открытых исходников этого репозитория вместе с файлом контрольных сумм `SHA256SUMS.txt`.

Перед запуском скачанного `GhostClip.exe` рекомендуется сверить контрольную сумму в PowerShell:

```powershell
Get-FileHash .\GhostClip.exe -Algorithm SHA256
```

Значение хэша должно посимвольно совпадать со строкой в файле `SHA256SUMS.txt` соответствующего релиза.

> **Почему может сработать Windows SmartScreen?**  
> Проект распространяется как открытое некоммерческое ПО без платного EV-сертификата подписи кода (Code Signing). Поэтому при первом запуске нового релиза Windows SmartScreen может показать предупреждение «Система Windows защитила ваш компьютер». Это ожидаемое поведение для неподписанных `.exe`: после сверки `SHA256SUMS.txt` нажмите **«Подробнее» → «Выполнить в любом случае»** либо запускайте программу напрямую из исходников командой `python main.py`.

## 4. Сообщение об уязвимостях

Если вы обнаружили ошибку безопасности, обход детектирования или потенциальную утечку данных:
1. Не публикуйте эксплойт или чувствительные данные в открытом виде до исправления.
2. Создайте отчёт через [GitHub Security Advisories](https://github.com/kdkdamls4-boop/GhostClip/security/advisories/new) или опишите проблему без реальных секретов в разделе [Issues](https://github.com/kdkdamls4-boop/GhostClip/issues).
3. Укажите версию GhostClip Shield, версию Windows (`winver`), шаги воспроизведения и ожидаемое поведение.
